## Abstract

After five interventions across `plan_relevance`, `plan_aux`, and `plan_unified` all regressed or were null, the bottleneck is not the detection-planning interface, perception-side feature shaping, or planning-aux predictions. This report inventories the remaining promising directions, drawn from gaps to HiP-AD, DiffusionDrive, DeMo, and DriveTransformer plus structural fixes to the current best model (`planpredtrajdeformmm_planinstfeat_laststage`, L2=0.522 / CR=0.047%). Highest-leverage candidates: soft-target mode supervision, more modes with diversity regularization, no-early-aggregation, and stage-1 planning supervision.

## Intro

The current best stage-2 planner is `planpredtrajdeformmm_planinstfeat_laststage` (L2=0.522, CR=0.047%). Recent attempts to push beyond it via auxiliary perception supervision (`detrel_s2`), planning aux heads (`planaux_da`, `planaux_conf`), or planning↔detection coupling (`alldet`, `bidir`) all regressed or were null. The mechanism gap to current SOTA approaches is now in the planner's own *output structure*, *supervision*, and *mode-modeling* — not in how it accesses perception.

Question:
- Among the remaining unexplored mechanisms, which are highest-leverage for L2 / CR given that interface-level changes have failed?

### Tier 1 — Quick fixes, single-config, high info-per-cost

| # | Config suffix | Change | Hypothesis |

## Results

### Batch A (Killarney, baseline `ptaux2d_ppdeformmm_planifls`)

Three single-mechanism toggles on the same baseline. Each adds one new flag in `MotionPlanningHead`; no other changes.

| # | Config suffix | Flag | Mechanism |
|---|---|---|---|
| 4 | `_modesofttgt` | `plan_mode_softtgt=True, plan_mode_softtgt_tau=1.0` | Replace winner-takes-all L1 reg loss with distance-softmax weighted L1 over all 6 cmd-indexed plan modes. Distances computed from cumulative XY; weights detached so they don't amplify mode collapse. |
| 1 | `_instfeataddls` | `planning_deformable_instfeat_additive=True` (gated by existing `_laststage`) | Last-stage planning deformable: query becomes `plan_mode_query + ego_feat_exp` (additive) instead of replacing `plan_mode_query` with `ego_feat_exp` and overwriting the ego token. Deformable output updates `plan_mode_query`; ego token in `instance_feature` is left untouched. |
| 3 | `_mmuniform` | `motion_deformable_multimode_uniform=True` | Motion deformable multimode aggregation uses uniform `1/fut_mode` weights instead of `softmax(motion_classification[-1])`. |

### Batch B (Killarney, baseline `ptaux2d_ppdeformmm_planifls`)

Three single-mechanism toggles testing capacity + structure of the planning mode bag.

| # | Config suffix | Flag(s) | Mechanism |
|---|---|---|---|
| 7 | `_modes20diverse` | `ego_fut_mode=20`, `plan_anchor=kmeans_plan_20.npy`, `plan_diversity_reg=True, plan_diversity_loss_weight=0.05, plan_diversity_sigma=5.0` | `ego_fut_mode` 6 → 20 (per cmd) with new k-means anchors; pairwise-similarity penalty across cmd-indexed plan modes (Gaussian kernel on flattened cumulative trajectories, summed over all pairs and averaged). Tests whether bigger mode bag plus diversity regularization improves trajectory accuracy. |
| 8 | `_noagg` | `mode_no_agg=True` | After motion / planning multimode deformable, skip the `softmax(cls)` aggregation that collapses per-mode attended features into the next decoder query. Per-mode attended features are written directly into `motion_mode_query` / `plan_mode_query` for the next stage; the `instance_feature` path uses uniform-mean aggregation to preserve shape. Mode-distinctness survives across decoder stages; refine and final cls do the mixing. |
| 9 | `_modetime36q` | `plan_mode_time_queries=True` (head and refine module) | Plan mode queries become `(bs, 3*ego_fut_mode, ego_fut_ts, D)` — one query per `(mode, ts)`. Each `(mode, ts)` query attends at its own waypoint anchor box; refine emits `(x, y)` per query via a shared MLP; mode classification collapses over time via mean before the cls MLP. Per-cmd: 6 modes × 6 timesteps = 36 queries. |
