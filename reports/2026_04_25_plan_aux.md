## Abstract

## Intro

The planning head is supervised almost entirely by L2 trajectory regression and mode classification. These losses tell the planner *where* to go but do not explicitly require it to reason about *why* — whether the plan is geometrically feasible, whether it stays on the road, or whether it conflicts with surrounding agents. The planner has access to map and detection features via cross-attention, but there is no training signal that forces it to actually read those features in a planning-critical way.

This batch tests whether adding auxiliary prediction tasks to the planning decoder improves planning. The auxiliary tasks are properties of candidate ego trajectories that can be computed directly from GT scene information: drivable area compliance (does each waypoint lie within the drivable region?) and object conflict (does any trajectory mode's future path overlap with a detected agent's predicted future?). These tasks do not change the planning head architecture — they add lightweight output heads and GT-derived loss terms. The key effect is that the planning cross-attention must learn to read map and detection features in order to predict these properties correctly.

This is complementary to `plan_relevance` (which teaches perception to encode planning-useful information) and `plan_unified` (which restructures how planning and perception interact). Here, the planning head itself is given richer scene-grounded supervision.

The high-level question: **can planning learn what is relevant from perception by being asked to predict planning-critical scene properties?**

Questions:
- Does drivable area compliance supervision improve trajectory accuracy and collision avoidance?
- Does object conflict supervision improve collision avoidance specifically?
- Are the two auxiliary tasks additive?
- Can the conflict predictions close the loop into `plan_relevance` as self-supervised relevance labels?

## Method

All experiments start from `ptaux2d_ppdeformmm_planifls` (DGX 3614) as the baseline. No changes to the stage-1 pretrain or planning architecture; only auxiliary output heads and loss terms are added.

**GT labels.**

- **Drivable area compliance**: per (planning mode, waypoint) binary label. Drivable mask is built per training sample from `map_geoms['boundary']` linestrings (already present in pipeline) by rasterizing boundaries as walls in a 0.5 m / pixel BEV grid covering `roi_size = (30, 60)` and flood-filling from the ego origin (which is drivable by construction). The new `RasterizeDrivableArea` pipeline step emits `gt_drivable_mask` of shape `(120, 60)`. At loss time, predicted-trajectory XY (cumsum of `plan_reg`) is bilinearly sampled into this mask via `grid_sample`; out-of-ROI waypoints are masked out of the loss.
- **Object conflict**: per (anchor, plan-mode) binary label, supervised only on Hungarian-matched anchors (mapping from `motion_loss_cache.indices`). Agent future positions in lidar frame: `gt_bboxes_3d[i, :2] + cumsum(gt_agent_fut_trajs[i])`. Ego future: `cumsum(plan_reg[m])`. Label = `min_t ||ego_t − agent_t||_2 < threshold` (default 2.0 m). Pos-weighted BCE (default `pos_weight=10`).

Both labels are computed on-the-fly during training using existing GT fields. The drivable mask uses only the boundary linestrings already produced by the offline data-prep step (no extra map loading at training time).

**Experiment 1 — `planaux_da`: drivable area compliance head.**
Add a small per-mode per-waypoint binary classification head (3-layer MLP, shared across modes/waypoints) to `MotionPlanningRefinementModule`, predicting drivable-area compliance for each candidate ego trajectory waypoint. Output shape `(bs, 1, M, ego_fut_ts)` where `M = 3 * ego_fut_mode = 18`. Supervised by BCE at every refine stage (3 stages), weighted by `da_loss_weight = 0.2`.

This forces the planning queries to encode map-grounded geometry — the planner cannot predict road compliance without reading the map token representations through the existing `cross_gnn` cross-attention.

Config: `ptaux2d_ppdeformmm_planifls_planaux_da`.

**Experiment 2 — `planaux_conf`: object conflict prediction head.**
Add a per-anchor × per-mode binary classification head (3-layer MLP on concat[`agent_feat_j`; `plan_query_m`]) to `MotionPlanningRefinementModule`. Output shape `(bs, num_anchor, M)`. Supervised by pos-weighted BCE (`pos_weight = 10`, `conflict_loss_weight = 0.2`), masked to Hungarian-matched anchors only.

This forces the planning queries to read the correct detection features for collision-critical agents — the head cannot predict conflict without learning to encode an agent's expected trajectory through cross-attention.

Config: `ptaux2d_ppdeformmm_planifls_planaux_conf`.

**Experiment 3 — `planaux_da_conf`: combined.**
Both drivable area and object conflict heads trained jointly. Tests whether the two auxiliary signals are additive.

Config: `ptaux2d_ppdeformmm_planifls_planaux_da_conf`.

**Experiment 4 — `planaux_selfrel`: closing the loop into perception.**
Use the trained object conflict predictions from Experiment 2 as self-supervised relevance labels for the detection head auxiliary head in `plan_relevance`. Agents predicted as high-conflict by the planner are labeled planning-relevant in the detection head. This closes the feedback loop between the two directions: planning's learned conflict model supervises perception's relevance representation without requiring GT labels at inference time. Depends on both Experiment 2 and `plan_relevance` Experiment 1 validating independently.

Config: combined with `plan_relevance` `selfrel` variant.

Implementation changes:
- `motion_blocks.py`: extend `MotionPlanningRefinementModule` with optional `with_da_head` and `with_conflict_head` MLP branches.
- `motion_planning_head.py`: collect new logits per refine stage, add `_loss_planning_da` (grid_sample on `gt_drivable_mask`) and `_loss_planning_conflict` (Hungarian-matched BCE) losses.
- `vectorize.py`: new `RasterizeDrivableArea` pipeline step emitting `gt_drivable_mask`.
- `transform.py` / pipelines `__init__.py`: wire new key through the adaptor.
- Configs: `ptaux2d_ppdeformmm_planifls_planaux_da` and `ptaux2d_ppdeformmm_planifls_planaux_conf` toggle the heads. `da` config also adds `RasterizeDrivableArea` to its train pipeline.

## Future Work

- If `planaux_conf` improves `obj_box_col`: the conflict supervision is directly shaping collision-avoidance behaviour; test with `rot3dv2` to see if the non-additivity is resolved when planning has explicit collision supervision.
- If `planaux_da` improves L2 without improving collision: map compliance and collision avoidance are separable; report them independently.
- If combined is additive: both auxiliary tasks address distinct gaps in the current supervision.
- Experiment 4 (`selfrel`): connect to `plan_relevance` once both individual experiments are validated.
- Combine with `plan_unified` findings: auxiliary supervision and tighter architectural coupling may compound.
